Hace cinco años escribía features de Cucumber en Newfold Digital.

Hoy construyo agentes de IA que escriben mis suites de tests.

Mismo título del puesto (QA Engineer). Un trabajo completamente distinto.

El cambio se dio de a poco:

- **2021:** Protractor/JS → Cucumber (sobre WebdriverIO)
- **2022:** Mantuve y refactoricé la suite de Cucumber — la regresión bajó de 3.5–6 h a ~1:45–2 h (~60%)
- **2024:** Re-platformé a Robot Framework + Python · flujos agénticos — la IA escribe los tests, yo reviso
- **2026:** Construí el Agentic QA Boilerplate (KATA + Playwright) — open-source, con un scaffolder create-agentic-qa, 20+ agent skills, una Xray CLI completa y 7 integraciones MCP
- **2026:** Lanzué mi portfolio de carrera en nelthor.com.ar — construido con flujos de dev agénticos

## Los Años en Newfold (2021–2026)

Entré a Newfold Digital como SDET trabajando en productos orientados al consumidor — networksolutions.com, bluehost.com — que atienden a millones de usuarios. Mi primera tarea fue hacerme cargo de una suite de más de 600 tests y volverla mantenible.

Empezamos migrándola de Protractor/JS a **Cucumber sobre WebdriverIO**, y después refactoricé esa suite por iniciativa propia — recortando la regresión de 3.5–6 h a ~1:45–2 h (~60%) mientras bajaba ~600–630 → ~430–440 casos. Alrededor de 2024 re-platformeamos a **Robot Framework + Python**, corriendo la cobertura de UI hacia tests de API/DB (headless) más rápidos — corre en menos de 1:30 h con cobertura igual y mayor precisión.

La lección clave: la arquitectura del framework importa más que la elección de herramientas. Una suite de tests bien estructurada sobrevive a cambios de equipo, pivotes de producto y renovaciones tecnológicas. Una mal estructurada se vuelve un pasivo.

## El Cambio Agéntico

En 2024 empecé a experimentar con generación de tests asistida por IA. Lo que comenzó como "a ver si ChatGPT puede escribir un test de Playwright" se convirtió en un flujo de trabajo agéntico completo:

1. La **IA propone** escenarios de test a partir de intención en lenguaje natural
2. **Reviso** correctitud, cobertura y edge cases
3. La **IA genera** el código de Playwright/Cucumber
4. **Apruebo** y hago merge

El cuello de botella se corrió de escribir código a **diseñar la intención**. Esa es la diferencia de Agentic QA.

## Lo Que Construí

El framework KATA (Component Action Test Architecture) surgió de este trabajo — un patrón de tres capas:

| Capa | Propósito | Quién la posee |
|-------|---------|-------------|
| Component | Qué testás | Dev |
| Action | Cómo interactuás | Framework |
| Test | Qué assertás | IA + Humano |

La IA encaja naturalmente en la Capa 3: genera aserciones a partir de intención en lenguaje natural mientras las capas de abstracción mantienen el framework estable.

Ese framework creció hasta convertirse en el **Agentic QA Boilerplate** — un starter open-source que convierte todo el ciclo de vida de QA en agent skills. En lugar de snippets de test aislados, orquesta el loop: shift-left testing (Stage 0), QA manual in-sprint (Stages 1–3), documentación de tests y priorización por ROI (Stage 4), automatización KATA (Stage 5), y regresión con sign-off GO/CAUTION/NO-GO (Stage 6). Se distribuye con un scaffolder `create-agentic-qa`, 20+ skills, una Xray CLI de 13 comandos para trazabilidad Jira/Xray, y 7 integraciones MCP.

La lección siguió siendo la misma: **diseñá tu framework para la colaboración con IA, no solo para el mantenimiento humano.**

## Mirando Hacia Adelante

Agentic QA no se trata de reemplazar ingenieros. Se trata de correr el trabajo de escribir código a **dirigir la calidad**. La IA maneja la mecánica; el ingeniero maneja la intención.

Eso es lo que significa Agentic QA Engineer para mí.
